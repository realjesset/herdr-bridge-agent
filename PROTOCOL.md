# Herdr Bridge MVP protocol

Mac app opens /usr/bin/ssh to a configured SSH alias (strict safe [A-Za-z0-9_.@-]+, cannot start '-'). StrictHostKeyChecking=yes, BatchMode=yes, ForwardAgent=no, ForwardX11=no, ClearAllForwardings=yes for detector stream; ServerAliveInterval=15 ServerAliveCountMax=2. Remote command is FIXED `~/.local/bin/herdr-bridge-agent --watch` (no dynamic remote shell arguments). Agent is a separately explicitly installed Python3 executable. No auto-installs, no HTTP API, no reverse forward, no token system.

Agent stdout is UTF-8 newline delimited JSON, maximum 65536 bytes per frame, maximum 128 services. A full snapshot every 3 seconds including unchanged/empty snapshots is the heartbeat:

{"version":1,"type":"snapshot","services":[{"id":"opaque-safe-id","pane":"pane-id","project":"project-label","port":5173,"host":"127.0.0.1"}]}

Only host 127.0.0.1 or ::1, TCP ports 1024..65535. id uses [A-Za-z0-9_.:-] max 128. pane/project control-free max 128 Unicode characters. Snapshot schema fully validated on Mac; duplicate IDs, duplicate host+port, oversized fields/frames/service counts, wrong version/type/ports/hosts rejected. Agent emits {"version":1,"type":"error","message":"sanitized diagnostic"} on detector failure, not a misleading empty snapshot. Detection must scope to same-UID processes rooted at Herdr pane foreground processes and loopback LISTEN sockets only. Exclude wildcard listeners and containers. Pane/project are labels only, never commands.

Mac owns approval state. New service -> pending + actionable notification (Forward/Ignore). Notifications reference ID and approval resolves only against the current validated snapshot. No forwarding before explicit click. IDs stable across hot reload in same pane host/port; suppress repeated notification within connection. Ignore and Stop suppress repeat prompt within connection; next connection requests new approval. Disappearance stops its tunnel. Stop never kills remote server. Disconnect/app exit/error/stale stream (15s) stops all tunnels and clears approvals. No reconnect automatically or remember approvals in MVP.

The detector SSH connection is a private control master (-M -S private path, directory 0700, ControlPersist=no, ClearAllForwardings=yes, -T). It runs the fixed detector command, not -N. Approvals use `ssh -S <private-path> -O forward -L 127.0.0.1:<port>:<host>:<port> <alias>` (::1 bracketed). Stop uses `-O cancel`. This clears inherited configured forwards at master startup and creates explicit approved forwards through the existing authenticated connection. User SSH config (including ProxyCommand) remains trusted. Only same local port, no auto remap. UI marks Connecting before Active; a successful control command confirms listener creation, not remote application health. Generation tokens prevent old callbacks or notification actions affecting new connections. Disconnect, protocol failure, heartbeat expiry, or uncertain cancel outcome closes the master to fail closed.

App menu: connection alias input/preferences, Connect/Disconnect, pending Forward/Ignore, active localhost URL Open/Stop, error status. Explicit HTTP browser opening only by click, unknown TCP protocols not assumed safe for auto open. Native macOS app via Swift Package (macOS 13+) and build script makes .app with Info.plist, LSUIElement and stable bundle ID. No auto-launch on login, telemetry, or updater.
